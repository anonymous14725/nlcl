A new way to think about code

What if words could build worlds?

NLCL is an open-source research prototype exploring natural language as a computational language. Instructions become semantic operations, operations shape a persistent intermediate representation, and that representation can generate code across multiple domains.

From sentence to system

One thought.
A complete pipeline.

NLCL treats language as more than a chat interface. A request is interpreted as candidate operations, checked against state, then represented in a reusable form before code is generated.

01

Say what you mean

Describe an object, behavior, connection, or system in everyday English.

02

Interpret intent

Map familiar sentence patterns to semantic tokens and candidate meanings.

03

Preview the change

Dry-run operations against a copy of the persistent state before acceptance.

04

Keep a universal IR

Store the result as a domain-aware intermediate representation you can inspect.

05

Generate and build

Use a domain module to generate code, then build, run, or simulate it.

Built to explore

Not just a parser.
A computational model.

⌘

Semantic operations

Atomic tokens such as CREATE, DELETE, and CONNECT can combine into higher-level operations.

◈

Persistent intermediate representation

Interpretations update a lasting state that can be inspected, built on, and translated into different targets.

⤳

Dry-run before acceptance

Vocabulary definitions are checked against a copy of state before they are accepted, helping keep changes inspectable.

⌁

Adaptive vocabulary

Teach aliases and define commands to extend the language with domain knowledge and custom patterns.

◎

Offline-first core

The core runs with Python’s standard library. The rule-based English parser works without a configured model backend.

⛭

Plugin-based domains

Modules can add specialized generators and connect entities through contracts such as HTTP, MQTT, serial, SPI, or I²C.

The shape of an intent

A living state,
not a one-off answer.

An instruction can become a structured operation, stay part of the project state, and inform what comes next. Here’s the style of IR shown in the project documentation.

Explore the README →
CREATE(domain=GAME, type=object,
  properties={"health": 100, "movable": true})
BEHAVIOR(target=hero, behavior={
  "on": "update",
  "if": "health < 1",
  "do": [{"op": "destroy"}]
})
CONNECT(target=temp, dst=monitor,
  via=http, properties={"interval_ms": 2000})
An honest prototype

Exploring a direction,
not claiming magic.

NLCL is an early research prototype. Its limits matter as much as its ambition.

↗

The offline parser supports common English sentence patterns; it is not unrestricted natural-language understanding.

↗

Persian and other non-Latin input require an online language-model backend.

↗

Generated code is a starting point, not a verified production product; toolchains may be needed for non-Python targets.

↗

Benchmark results are preliminary and based on a small, author-created corpus.
